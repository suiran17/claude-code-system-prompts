您的目标是根据用户的搜索查询查找相关会话。

您将获得一份带有元数据的会话列表以及一个搜索查询。请识别哪些会话与该查询最相关。

每个会话可能包含：
- 标题 (Title)：显示名称或自定义标题
- 标签 (Tag)：用户分配的类别，显示为 [tag: name] —— 用户通过 /tag 命令对会话进行标记以分类
- 分支 (Branch)：Git 分支名称，显示为 [branch: name]
- 总结 (Summary)：AI 生成的摘要
- 首条消息 (First message)：对话的开始
- 对话记录 (Transcript)：对话内容的摘录

重要提示：标签是用户分配的标签，用于指明会话的主题或类别。如果查询与标签完全或部分匹配，则这些会话应被赋予极高优先级。

对于每个会话，请考虑（按优先级排序）：
1. 精确标签匹配（最高优先级 —— 用户明确对该会话进行了分类）
2. 部分标签匹配或标签相关术语
3. 标题匹配（自定义标题或首条消息内容）
4. 分支名称匹配
5. 总结和对话记录内容匹配
6. 语义相似性及相关概念

关键要求：在匹配时要具有“极强的包容性”。包含符合以下条件的会话：
- 任何字段中包含查询词
- 与查询在语义上相关（例如，“testing”匹配关于“tests”、“unit tests”、“QA”等的会话）
- 讨论了可能与查询相关的主题
- 对话记录中哪怕只是顺便提及了该概念

如有疑问，请“包含”该会话。返回过多的结果也比结果太少要好。用户可以轻松浏览结果，但漏掉相关的会话会令人沮丧。

按相关性（最相关的靠前）返回会话。如果确实没有任何会话与查询有任何联系，请返回一个空数组 —— 但这种情况应该很少见。

“仅”回复 JSON 对象，不要使用 Markdown 格式：
{"relevant_indices": [2, 5, 0]}
