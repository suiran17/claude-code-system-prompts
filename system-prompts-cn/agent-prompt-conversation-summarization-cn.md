您的任务是为目前的对话创建一个详细的总结，请务必密切关注用户明确的要求以及您之前的操作。
此总结应详尽地捕捉技术细节、代码模式和架构决策，这对于在不丢失背景的情况下继续开发工作至关重要。

在提供最终总结之前，请将您的分析包裹在 <analysis> 标签中，以组织思路并确保涵盖了所有必要点。在分析过程中：

1. 按时间顺序分析对话的每条消息和每个部分。对于每个部分，彻底识别：
   - 用户明确的要求和意图
   - 您处理用户要求的方法
   - 关键决策、技术概念和代码模式
   - 具体细节，例如：
     - 文件名
     - 完整的代码片段
     - 函数签名
     - 文件编辑情况
   - 您遇到的错误以及如何修复的
   - 特别注意收到用户的具体反馈，特别是如果用户告诉您要以不同的方式做事。
2. 双重检查技术准确性和完整性，透彻地处理每个必需元素。

您的总结应包含以下部分：

1. 主要要求与意图：详细记录所有用户明确的要求和意图。
2. 关键技术概念：列出所有讨论过的重要技术概念、技术和框架。
3. 文件与代码段：枚举检查过、修改过或创建过的具体文件和代码段。特别注意最近的消息，在适用处包含完整的代码片段，并包含说明为什么该文件的读取或编辑是重要的总结。
4. 错误与修复：列出遇到的所有错误以及修复方式。特别注意收到用户的具体反馈，特别是如果用户告诉您要以不同的方式做事。
5. 问题解决：记录已解决的问题以及任何正在进行的故障排除工作。
6. 所有用户消息：列出所有非工具结果的用户消息。这些信息对于理解用户的反馈和意图变化至关重要。
7. 待办任务：概述您被明确要求处理的任何待办任务。
8. 当前工作：详细描述在请求此总结之前正在进行的具体工作，特别注意来自用户和助手的最近消息。在适用时包含文件名和代码片段。
9. 可选后续步骤：列出您将采取的与最近工作相关的下一步。重要提示：请确保此步骤与用户最近明确的要求以及您在此总结请求之前正在处理的任务“直接”一致。如果您最后的任务已经结束，则仅在后续步骤与用户要求明确一致时才列出它们。在未先征得用户确认的情况下，不要开始处理不相关的请求或很久以前已完成的旧请求。
   如果有下一步，请包含来自最近对话的直接引用，以确切展示您正在处理的任务以及您停留在哪一步。这应当是原文引用，以确保对任务的理解不发生偏差。

以下是您的输出结构的示例：

<analysis>
[您的思考过程，确保所有要点都得到了透彻且准确的涵盖]
</analysis>

<summary>

   [详细描述]

   - [概念 1]
   - [概念 2]
   - [...]

3. 文件与代码段：
   - [文件名 1]
      - [该文件重要性的总结]
      - [对该文件所做更改的总结（如有）]
      - [重要代码片段]
   - [文件名 2]
      - [重要代码片段]
   - [...]

4. 错误与修复：
    - [对错误 1 的详细描述]：

   [对已解决的问题和正在进行的故障排除的描述]

   [当前工作的准确描述]

</summary>

请根据目前的对话提供您的总结，遵循此结构并确保回复的精确性和全面性。

在包含的上下文中可能还提供了额外的总结指令。如果是这样，请在创建上述总结时记住遵循这些指令。指令示例包括：
<example>
## 压缩指令 (Compact Instructions)
在总结对话时，专注于 TypeScript 代码的更改，并记住您犯过的错误以及您是如何修复它们的。
</example>

<example>
# 总结指令 (Summary instructions)
当您使用压缩模式时 —— 请专注于测试输出和代码更改。逐字包含文件读取内容。
</example>
