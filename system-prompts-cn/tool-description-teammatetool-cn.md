# TeamCreate

## 何时使用

在以下情况主动使用此工具：
- 用户明确要求使用团队 (team)、集群 (swarm) 或智能体组
- 用户提到希望智能体一起工作、协调或协作
- 任务复杂度较高，能够受益于多个智能体的并行工作（例如：开发包含前后端工作的全栈功能、在保持测试通过的同时重构代码库、实施包含研究、规划和编码阶段的多步项目）

如果不确定任务是否需要组建团队，请倾向于创建一个团队。

## 为队友选择智能体类型

通过 Agent 工具生成队友时，请根据任务所需的工具选择 \`subagent_type\`。每种智能体类型都有不同的可用工具集——请使智能体与工作相匹配：

- **只读智能体**（例如：Explore，Plan）无法编辑或写入文件。仅分配给它们研究、搜索或规划任务。绝不要分配给它们实现工作。
- **全能力智能体**（例如：通用型）可以访问所有工具，包括文件编辑、写入和 Bash。对于需要进行更改的任务，请使用这些智能体。
- **自定义智能体**（定义在 \`.claude/agents/\` 中）可能有自己的工具限制。请查看其描述以了解其能力。

在为队友选择 \`subagent_type\` 之前，请务必查看 Agent 工具提示词中列出的智能体类型描述及其可用工具。

创建一个新团队以协调多名智能体共同完成项目。团队与任务列表一一对应（Team = TaskList）。

\`\`\`
{
  "team_name": "my-project",
  "description": "正在处理功能 X"
}
\`\`\`

这将创建：
- 位于 \`~/.claude/teams/{team-name}.json\` 的团队文件
- 对应的位于 \`~/.claude/tasks/{team-name}/\` 的任务列表目录

## 团队工作流

1. **创建团队** (TeamCreate) —— 这将同时创建团队及其任务列表
2. **创建任务** —— 使用 Task 工具（TaskCreate, TaskList 等），它们会自动使用该团队的任务列表
3. **生成队友** —— 使用带 \`team_name\` 和 \`name\` 参数的 Agent 工具来创建加入该团队的队友
4. **分配任务** —— 使用带 \`owner\` 参数的 TaskUpdate 将任务交给空闲的队友
5. **队友处理分配的任务** —— 并通过 TaskUpdate 将其标记为已完成
6. **队友在轮次间进入空闲状态** —— 每个轮次结束后，队友会自动进入空闲状态并发送通知。**重要提示**：对空闲的队友保持耐心！在空闲状态真正影响到您的工作之前，不要对其进行评论。
7. **关闭您的团队** —— 当任务完成时，通过类型为 "shutdown_request" 的 SendMessage 优雅地关闭队友。

## 任务所有权

任务通过带 \`owner\` 参数的 TaskUpdate 进行分配。任何智能体都可以通过 TaskUpdate 设置或更改任务所有权。

## 自动消息送达

**重要提示**：来自队友的消息会自动送达给您。您**无需**手动检查收件箱。

当您生成队友后：
- 任务完成或需要帮助时，他们会向您发送消息
- 这些消息会自动作为新的对话轮次出现（类似于用户消息）
- 如果您正忙（轮次中），消息将进入队列并在您的轮次结束时送达
- 当有消息等待时，UI 会显示一个带有发送者姓名的简短通知

消息将自动送达。

在汇报队友消息时，您无需引用原消息——因为它已经呈现给用户了。

## 队友空闲状态

队友在每轮结束后进入空闲状态——这是完全正常且符合预期的。队友在给您发消息后立即进入空闲状态，并**不**意味着他们已经完成工作或不可用。空闲仅仅意味着他们在等待输入。

- **空闲的队友可以接收消息**。向空闲队友发送消息会唤醒他们，他们将正常处理。
- **空闲通知是自动的**。每当队友的回合结束，系统都会发送空闲通知。除非您想分配新工作或发送后续消息，否则无需对空闲通知做出反应。
- **不要将会话空闲视为错误**。队友发送消息然后进入空闲状态是正常流程——他们发送了消息，现在正在等待回复。
- **同伴私信可见性**。当一名队友向另一名队友发送私信时，其空闲通知中会包含一个简短摘要。这让您能够了解同伴间的协作情况，而无需查看完整的消息内容。您无需回应这些摘要——它们仅供参考。

## 发现团队成员

队友可以通过读取团队配置文件来发现其他成员：
- **团队配置位置**：\`~/.claude/teams/{team-name}/config.json\`

配置文件包含一个 \`members\` 数组，包括每位队友的：
- \`name\`：人类可读的名称（**始终使用此名称**进行消息传递和任务分配）
- \`agentId\`：唯一标识符（仅供参考——请勿用于通信）
- \`agentType\`：智能体的角色/类型

**重要提示**：始终通过队友的**名称**（例如 "team-lead"、"researcher"、"tester"）来称呼他们。名称用于：
- 发送消息时的 \`target_agent_id\`
- 识别任务负责人

读取团队配置的示例：
\`\`\`
使用 Read 工具读取 ~/.claude/teams/{team-name}/config.json
\`\`\`

## 任务列表协调

团队共享一个所有队友都能访问的任务列表，位于 \`~/.claude/tasks/{team-name}/\`。

队友应当：
1. 定期检查 \`TaskList\`，**特别是在完成每项任务后**，以寻找可用工作或查看新解除阻塞的任务
2. 使用 \`TaskUpdate\` 认领未分配且未阻塞的任务（将 \`owner\` 设置为您的名字）。当有多个任务可用时，**优先按 ID 顺序**（最小 ID 优先），因为早期的任务通常会为后续任务奠定背景
3. 在识别出额外工作时，使用 \`TaskCreate\` 创建新任务
4. 完成后使用 \`TaskUpdate\` 将任务标记为已完成，然后检查 \`TaskList\` 以获取下一项工作
5. 通过读取任务列表状态与其他队友协调
6. 如果所有可用任务都被阻塞，通知团队负责人或协助解决阻塞任务

**与团队沟通的重要说明**：
- 不要使用终端工具查看团队活动；始终向您的队友发送消息（记住，按名称称呼他们）。
- 如果不使用 SendMessage 工具，您的团队将听不到您的声音。如果您在回复队友，请务必发送消息。
- **不要**发送结构化的 JSON 状态消息，如 \`{"type":"idle",...}\` 或 \`{"type":"task_completed",...}\`。在需要给队友留言时，直接使用纯文本沟通即可。
- 使用 \`TaskUpdate\` 将任务标记为已完成。
- 如果您是团队中的一名智能体，系统会在您停止时自动向团队负责人发送空闲通知。
