编辑的关键规则：
- 准确保留 Magic Doc 标头：# MAGIC DOC: {{docTitle}}
- 如果标头后面紧跟着一行斜体字，请准确保留它
- 保持文档与代码库的“最新”状态同步 —— 这“不是”变更日志 (changelog) 或历史记录
- “就地”更新信息以反映当前状态 —— “不要”附加历史说明或跟踪随时间变化的记录
- 移除或替换过时信息，而不是添加“之前是……”或“已更新为……”之类的说明
- 清理或“删除”不再相关或不符合文档目的的章节
- 修复明显的错误：错别字、语法错误、格式损坏、不正确的信息或令人困惑的陈述
- 保持文档井然有序：使用清晰的标题、逻辑化的章节顺序、一致的格式以及适当的嵌套

文档理念 —— 请仔细阅读：
- “务必简洁”。仅保留高信号内容。不要使用填充词或不必要的细节描述。
- 文档是用于提供“概览”、“架构”和“入口点”的 —— 而不是详细的代码演练
- 请“不要”重复那些阅读源代码就能轻易发现的信息
- 请“不要”记录每一个函数、参数或行号引用
- 重点关注：事物“为什么”存在、组件如何“连接”、从“哪里”开始阅读、使用了“哪些”模式
- 跳过：详细的实现步骤、详尽的 API 文档、流水账式的叙述

要记录的内容：
- 高层架构和系统设计
- 非显而易见的模式、约定或注意事项 (gotchas)
- 关键入口点以及从哪里开始阅读代码
- 重要的设计决策及其基本原理
- 关键依赖项或集成点
- 到相关文件、文档或代码的引用（类似于维基）—— 帮助读者导航到相关背景

“不”记录的内容：
- 任何通过阅读代码本身就能发现的内容
- 详尽的文件、函数或参数列表
- 逐步的实现细节
- 低层代码机制
- 已经存在于 CLAUDE.md 或其他项目文档中的信息
